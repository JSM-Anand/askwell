1. **Vercel variables do not reach Preview (found in the logs).** Vercel project `askwell`, read through the API (names and targets only):

   | Variable | Targets now | Needed |
   |---|---|---|
   | `GEMINI_API_KEY` | production | add preview |
   | `ARCJET_KEY` | production | add preview |
   | `CLERK_WEBHOOK_SIGNING_SECRET` | not set anywhere | add for production and preview (the `whsec_` of the Clerk endpoint, no quotes or newline) |
   | `LANDING_WIDGET_KEY`, `NEXT_PUBLIC_APP_URL` | not set anywhere | add as wanted (P6H-T04) |
   | `OPENAI_API_KEY` | production | stale, delete |

   Runtime logs of the #51 preview: `Processing source: embedding model gemini-embedding-2, 1536 dimensions, GEMINI_API_KEY missing`, then `Processing pasted text failed Error: Missing environment variable GEMINI_API_KEY`, and for chat `POST /api/widget/chat failed after counting Error: Missing environment variable GEMINI_API_KEY`. Runtime log of the #50 preview: `Clerk webhook cannot run: CLERK_WEBHOOK_SIGNING_SECRET is missing or empty`. So the Gemini failure on previews and the webhook not flipping the plan have the same cause: a missing variable, not quotes or the SDK. No code change is needed.

2. **Arcjet fails open without a key (decision for the lead, not changed here).** `apps/web/lib/security/arcjet.ts` allows the request and logs `Arcjet failed on chat, allowing the request: ARCJET_KEY is not set`. Previews had no key until it was added to Preview at 05:57 UTC on 2026-11-03 (it applies after a redeploy), so until then they had no rate limit and no injection check; this showed up in the #51 preview log. Production has the key. The same fail-open also covers an Arcjet error or a thrown `protect` call, with the key set. If the product owner wants the public routes to fail closed (missing key, or Arcjet erroring) in production, that is a behaviour change (a task of its own): chat would then break whenever Arcjet does. I left it as is.
